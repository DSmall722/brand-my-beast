# BrandMyBeast — P2 auth + soft auction scaffold

CAMPAIGN.md still wins. This file records the **P2** build choices so agents do not reopen them in drive-by PRs.

Updated: 2026-09-14

## Auth vendor (locked for P2)

**Choice: Auth.js (Auth.js / `next-auth` v5) on the App Router.**

Why this over Clerk / Neon Auth for v1:

- Stays inside the locked Next.js + Vercel stack without a second paid identity SaaS.
- Email magic-link / OAuth can land later; P2 only needs “account exists” for intent bids.
- Session lives on the server. No `localStorage` ledger.

Wiring Auth.js routes, providers, and env secrets is a **follow-up PR**. This scaffold only locks the vendor name so soft-auction types can assume a `userId` string from Auth.js.

Do **not** add Clerk, Supabase Auth, or Firebase Auth without a PR that rewrites this section.

## Soft auction (intent only)

P2 standing bids are **intent**, not capture:

- Record who wants which panel at what mark.
- Show deposit **20%** as an amount owed later — never charge a card on P2.
- Operator approval / veto stays manual.
- No Stripe SetupIntent, no `CLOSE_AT`, no 30-day clock.

Domain helpers live in `src/lib/intent.ts` (increment + deposit math from `RULES.md`). Persistence and UI for panel bid pages ship in later P2 PRs.

## Out of scope until P3

- Stripe SetupIntent / card capture
- Setting `CLOSE_AT` / starting the 30-day clock
- Wreck clause cash path (contract text can draft earlier; money path waits)
- Tweet / public X automation
